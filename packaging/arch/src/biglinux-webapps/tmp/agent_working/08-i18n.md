## Plural-form audit

Five count-bearing strings currently use `gettext(...).replace("{n}", …)` instead of `ngettext`:

| file:line | string | n source |
|---|---|---|
| `webapps-manager/src/webapp_dialog/handlers/media.rs:50` | `"Icon candidate {n}"` | `index + 1` |
| `webapps-manager/src/window/list.rs:37` | `"{} results"` | result count |
| `webapps-manager/src/window/actions/import_export.rs:101` | `"Imported {imported}, skipped {dups} duplicates"` | both counts |
| `webapps-manager/src/window/actions/remove_multiple.rs:218` | `"{count} WebApps removed"` | success count |
| `webapps-manager/src/window/actions/remove_multiple.rs:220` | `"{ok} removed, {fail} failed"` | both counts |

`gettextrs` exposes `ngettext("singular", "plural", n)` which lets translators distribute the plural-form rule per language (Russian's three forms, Arabic's six, Slovenian's four, etc.). The current `replace` shortcut hard-codes English-style plurality, so e.g. Polish and Russian translations cannot express the correct form even if the catalogue stores it.

Severity: **medium**. These are visible counts on common actions. Not blocking 100% coverage gate (those use gettext correctly for the *singular case*), but a follow-up sweep should convert them all to `ngettext`.
